# M4 Desktop Launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A desktop launcher that takes a player who isn't technical from their host's invite link to the game's lobby on Linux: a server list like Minecraft's, accounts, their own copy checked, downloaded and repaired through DepotDownloader, Play through umu-run, and signed self-updates, in the design the owner approved.

**Architecture:** `crates/fenji-launcher` gains the launcher's model (`app/`), which owns every piece of state and every secret and publishes a `Snapshot` on each change. `apps/launcher/src-tauri` is a thin Tauri 2 shell outside the Cargo workspace: one `intent` command, one `snapshot` event, and the few things only it can do (the window, the folder dialog, links, updates). `apps/launcher/src` is a TypeScript view with no framework that renders snapshots into the approved boards' screens. Golden snapshot files are the contract between the two sides.

**Tech Stack:** Rust 1.97.1 (edition 2024), tokio, reqwest 0.13 with rustls, `zip` 9 and `tar` 0.4 (fetched tools), Tauri 2.12 with its updater, dialog, opener and single-instance plugins; TypeScript 7, Vite 8, vitest 5 with jsdom 30, pnpm 12, Node 24; DepotDownloader 3.4.0 and umu-launcher 1.4.4, fetched on first use; GitHub Actions.

**Spec:** [`docs/superpowers/specs/2026-10-15-m4-launcher-design.md`](../specs/2026-10-15-m4-launcher-design.md) (#285), under the [M4 umbrella spec](../specs/2026-10-13-m4-social-sandbox-design.md) §3.3 and §4, with the [hosting spec](../specs/2026-10-14-m4-hosting-design.md) §3.8–§3.11 and HA6. Written and approved under the owner's pre-approval of 2026-10-15. The design is [`DESIGN.md`](../../../DESIGN.md) and the boards in [`docs/design/launcher/`](../../design/launcher/README.md).

## Global Constraints

- **Ground rules** (CLAUDE.md). Rule 7 above all: no code of Fenji's reads a Steam or Gameforge login or password; the Steam sign-in happens in DepotDownloader's own terminal window, by QR code (spec L3). Rule 1: nothing from the game ships with the launcher or downloads from Fenji. Cloud tasks are repository-only: nothing from `re/`, the game client or its files.
- **No telemetry.** The launcher connects only to the servers in its list, to `github.com` for its update check and the two pinned tools, and nothing else. Nothing about the player is sent anywhere.
- **Secrets never touch disk or the view.** A password lives in one intent and is dropped after its request. Session tokens and game tickets stay in the Rust model and never appear in a `Snapshot`, a log line, `settings.json` or an error's text.
- **Server text is untrusted.** Names, MOTDs, maintenance messages, ban reasons, host names and player names reach the view as data, and the view writes them with `textContent`, never `innerHTML`.

## Review Focus

The inputs and failures the spec implies that a player would hit first, each pinned by a test in the task that owns the code:
1. **Secrets escaping.** After a whole flow (redeem, sign in, Play), the password, the session token and the ticket appear in no `Snapshot` JSON, no log line and not in `settings.json`. Tasks 8 and 10.
2. **Hostile server text in the view.** A server named `<img src=x onerror=alert(1)>`, with a MOTD and a player name like it, shows those characters literally, and no element is created from them. Tasks 12 and 13.
3. **A server that never answers.** A server that accepts connections and never replies goes offline after 5 s, and meanwhile every other intent and the snapshot stream carry on: no lock is held across a request. Task 8.
4. **A download window closed mid-way.** When the player closes DepotDownloader's terminal (no status file, its processes gone), the download ends as stopped within 5 s, never "downloading" for ever. Task 7.
5. **A damaged settings file.** A `settings.json` that doesn't parse is moved aside as `settings.json.bad`, the launcher starts with defaults, and the notice says so. Task 4.

## Rulings made while planning

- **LP1:** The shell has one command, `intent`, taking a tagged enum, instead of one command per intent (spec §3.1), so the shell never changes when an intent is added. `fixtures/intents.json` holds one example of each, which Rust deserializes and TypeScript type-checks — cost if wrong: one command per intent later.
- **LP2:** Golden snapshots are built by hand in `app::golden` and checked against the JSON files; the model's behaviour is tested apart, against a real in-process server in `crates/fenji-server/tests/launcher_app.rs` — cost if wrong: none (more tests, not fewer).
- **LP3:** The model uses `ApiClient` directly, with no trait to fake it; its tests run against the real server, as M3's launcher tests do — cost if wrong: a trait later.
- **LP4:** A screen mounts once per route and updates in place on each snapshot, so a form keeps its input and focus while the state changes around it — cost if wrong: none.
- **LP5:** The context column's people heading reads "Playing now", and the status line counts friends "playing" ("3 friends playing"): with the world, players are in the lobby or the world, and the API can't tell which (the boards' "In the lobby" was true only in M3) — cost if wrong: two strings.
- **LP6:** A repair passes `-validate` with `-filelist`, so DepotDownloader re-checks the listed files' chunks instead of trusting its own state — cost if wrong: a slower repair.
- **LP7:** An invite code without a link redeems on the active server; with no server saved, the launcher asks for the whole link, since a code alone names no server — cost if wrong: an address field on Welcome.
- **LP8:** Play without a session sets `needSignIn`; the view shows Sign in, and a successful sign-in carries on with Play — cost if wrong: a second Play press.
- **LP9:** A server state this launcher doesn't know counts as incompatible ("runs a newer Fenji"), like a newer API version — cost if wrong: it shows as online.
- **LP10:** The shell, not the view, opens the folder dialog and links, and minimises and closes the window, through intents. The view's capability holds only the shell's command, its events and window dragging — cost if wrong: two plugin permissions on the view.
- **LP11:** Updates are checked, downloaded and installed by the shell in Rust with `tauri-plugin-updater`, so no updater or process plugin is exposed to the view — cost if wrong: none.
- **LP12:** The release workflow assembles `latest.json` with a small script (`scripts/launcher-latest-json.sh`) instead of a third-party action — cost if wrong: one more pinned action.
- **LP13:** The view's TypeScript types for snapshots and intents are generated from the Rust types by `ts-rs` (MIT; a dev-dependency, `#[cfg_attr(test, derive(TS))]`) into `apps/launcher/src/gen/` when the model's tests run, and CI fails when the committed files are stale, so the two sides can't drift — cost if wrong: hand-written types and a drift test.

```rust
fn a_full_check_reports_each_file_and_ends_at_one_hundred_percent() {
    let dir = tempfile::tempdir().unwrap();
    let m = folder_with(dir.path(), &[("a.bin", 10_000), ("bin64/b.dll", 20), ("c/d.txt", 5)]);
    let seen = std::sync::Mutex::new(Vec::new());
```

- [ ] **Step 1: Write the failing tests.** A test server serves bytes from a route; archives are built in the test with the `zip` and `tar` crates' writers.

```rust
async fn serve(bytes: Vec<u8>) -> String {
    let app = axum::Router::new().route("/t", axum::routing::get(move || async move { bytes.clone() }));
    let listener = tokio::net::TcpListener::bind("127.0.0.1:0").await.unwrap();
    let addr = listener.local_addr().unwrap();
    tokio::spawn(async move { axum::serve(listener, app).await.unwrap() });
    format!("http://{addr}/t")
}

fn zip_with(entries: &[(&str, &[u8])]) -> Vec<u8> {
    let mut out = std::io::Cursor::new(Vec::new());
    let mut z = zip::ZipWriter::new(&mut out);
    for (name, body) in entries {
        z.start_file(*name, zip::write::SimpleFileOptions::default()).unwrap();
        std::io::Write::write_all(&mut z, body).unwrap();
    }
    z.finish().unwrap();
    out.into_inner()
}

fn tool(url: String, body: &[u8], archive: Archive, member: &str) -> Tool {
    use sha2::{Digest, Sha256};
    Tool { name: "Thing".into(), version: "1.0".into(), url, sha256: Sha256::digest(body).into(), archive, member: member.into() }
}

#[tokio::test]
async fn a_tool_is_fetched_checked_and_only_its_member_unpacked() {
    let body = zip_with(&[("Thing", b"#!/bin/sh\necho hi\n"), ("LICENSE", b"text"), ("../evil", b"x")]);
    let dir = tempfile::tempdir().unwrap();
    let t = tool(serve(body.clone()).await, &body, Archive::Zip, "Thing");
    let path = ensure(&t, dir.path(), &|_, _| {}).await.unwrap();
    assert_eq!(path, dir.path().join("Thing-1.0/Thing"));
    assert_eq!(std::fs::read(&path).unwrap(), b"#!/bin/sh\necho hi\n");
    #[cfg(unix)]
    assert_eq!(std::os::unix::fs::PermissionsExt::mode(&std::fs::metadata(&path).unwrap().permissions()) & 0o777, 0o755);
    assert!(!dir.path().join("Thing-1.0/LICENSE").exists() && !dir.path().join("evil").exists());
    assert_eq!(installed(&t, dir.path()), Some(path));
}
```

  | Constant | Sentence |
  |---|---|
  | `DOWNLOAD_LINUX_ONLY` | "Downloading with Steam works on Linux only for now." |
  | `BUSY` | "Something is already running: wait for it to finish, or stop it." |
  | `NO_TERMINAL` | "Fenji couldn't open a terminal for DepotDownloader. Run this in yours:" |
  | `CHECK_STOPPED` | "The check was stopped." |
  | `DOWNLOAD_CANCELLED` | "The download was cancelled." |
  | `WINDOW_CLOSED` | "DepotDownloader's window closed before the download finished. Try again." |
  | `NOTHING_TO_REPAIR` | "Every file checked out last time: there's nothing to repair." |
  | `download_stopped(code)` | "The download stopped: DepotDownloader ended with {code}. Try again." |

- **The rules:**
  - **ChooseFolder** saves the folder, then runs a quick check. A saved folder gets a quick check when the launcher starts.
  - **Check** runs `verify_with` on a blocking thread, as `job: Checking`, publishing at most ten times a second. A stop clears the job, keeps the last result and sets `CHECK_STOPPED` as an info notice. A folder that's gone is `FolderMissing`.
  - **One job at a time:** any of these while a job runs is refused with `BUSY`.
  - **Download** is refused off Linux with `DOWNLOAD_LINUX_ONLY`. On Linux:
    1. It finds DepotDownloader: `AppConfig.depot_downloader`, or else `tools::ensure` into `<data dir>/tools`, shown as `job: Fetching`.
    2. It finds a terminal: `AppConfig.terminal`, or else `find_terminal` over `AppConfig.env`. With none, it's refused with `NO_TERMINAL`, and the view shows `client.manualCommand`.
    3. It starts a `DepotRun` in `<data dir>/depot/<unix ms>` and polls it every 500 ms:
       - `Waiting` → `Downloading { waiting_for_steam: true }`;
       - `Running` → its percentage and file;
       - `Ended { 0 }` → saves the folder, then runs a full check;
       - `Ended { n }` → `download_stopped(n)`;
       - `Lost` → `WINDOW_CLOSED`, or `DOWNLOAD_CANCELLED` after a `CancelDownload`.
  - **Repair** is refused with `NOTHING_TO_REPAIR` unless the last check is `NeedsRepair`. It downloads as above, with `files` set to the failing paths. On `Ended { 0 }`, a full check of those files only follows, through a manifest of just their entries. The result is `Verified { full }` when they all check out, and otherwise `NeedsRepair` with what still fails.
  - **`manualCommand`** is `Some` whenever the system can download: `manual_command(folder or default, None)`.
  - **`defaultFolder`** is `<home>/Games/SoLO`.
